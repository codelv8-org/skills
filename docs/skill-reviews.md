# Community Skill Ratings & Reviews

The GitHub Pages catalog remains static. No OAuth client secret, PAT, or database is embedded in the browser.

## Submit a review
Open any skill's detail modal, expand the review form, select your actual AI agent, and give 1–5 stars in each of five dimensions. The overall score is their arithmetic mean. Continue to GitHub to sign in and **submit the public Issue**. The website does not submit it automatically. The text is optional, at most 500 characters. Never include PII, patient information, credentials, internal source data, or other secrets.

The issue title and the structured first lines are required. Use the catalog form for the correct skill ID and version. To revise a review, edit its original issue and ask for reapproval instead of submitting a duplicate.

## Maintainer setup (once)
In [Issues → Labels](https://github.com/codelv8-org/skills/labels), create exactly `skill-review-approved` (suggested color `0e8a16`). No separate external service or GitHub PAT is needed. Confirm Pages deployment via GitHub Actions and allow the standard workflow token to read issues.

## Moderation
Review each submission for format, real use, authentic version, spam, abuse, personal/sensitive data, and disclosure. Apply `skill-review-approved` **only after** approving the exact issue body. Removing the label withdraws the review. Edited issues (including edits in the same second as approval) are excluded until a maintainer removes/reapplies the label after rechecking. If multiple reviews by the same GitHub user ID for a skill/version are approved, the most recently approved wins. The latest version alone determines catalog ratings and ranking; historical versions and agent filters are available in the detail modal. GitHub accounts are authenticated, but actual skill usage is not independently verified.

Labels, relevant issue edits/deletions/transfers, pushes, manual dispatch, and a daily refresh rebuild the static dataset. This is eventually consistent, not real-time. If an issue is public, its original contents are public even before catalog approval; do not submit sensitive data. The JSON builder fails closed for missing approvals and fails the deployment on API errors instead of replacing existing scores with invented zeroes. A moderator should remove the label and redact/remove the original issue when necessary; GitHub Pages/CDN copies may remain briefly.

## Local development
Run `node --test scripts/skill-ratings.test.mjs` and `node --check assets/js/skill-reviews.js`. To build with real GitHub data, use a secure environment with read-only issues permission, `GITHUB_TOKEN`, and `GITHUB_REPOSITORY=codelv8-org/skills`. The deploy workflow sets these automatically. The checked-in JSON files intentionally contain no sample ratings. Review text is rendered using textContent, never injected as HTML.


## Community Edition — Phase 2
- **Helpful vote:** open the source Issue and click GitHub's thumbs-up reaction. The catalog shows the native +1 count at the last deployment, not an independent verified-user count. Sorting by Helpful is available. Reaction-only changes refresh on the daily schedule or manual Pages rebuild, because GitHub issues workflows do not emit a reaction event.
- **Images:** upload up to three public screenshots to the Issue before submitting it. Use GitHub's own attachment markup (one image per line, `https://github.com/user-attachments/assets/<UUID>`). A maintainer must inspect both text and images before approving. Images use safe URLs and lazy loading; no third-party image URLs are embedded. Images are public even before review approval; never upload patient information, identity photos, secrets, or internal material.
- **Comparison:** choose 2–3 distinct skills to compare current-version score, review count, five dimensions, supported agents and static benchmark. No ratings appear as em dashes.
- **Quality analytics:** current-version aggregate, Helpful counts, version history, agent breakdown, and benchmark check results. Historical versions do not contaminate current ratings.
- **Automated benchmark:** nine deterministic checks against the actual checked-out repository (canonical entry, name, activation description, source/catalog version, agents, declared assets, local links, workflow file and pinned-source freshness). This is a repository structural benchmark, NOT model output quality, token efficiency, or visual fidelity; the output evaluation status is always NOT RUN unless separate measured evaluations are implemented. A failed check is reported rather than hidden. The catalog metadata for photoreal-head-web now shows its actual source version 3.0.0; its older pinned workflow remains flagged until regenerated.
- **AI Review Summary:** statistics are available without credentials; AI is opt-in. Set repository variable `SKILL_REVIEW_AI_ENABLED=true`, variable `SKILL_REVIEW_AI_MODEL` to a supported OpenAI API model, and secret `OPENAI_API_KEY`. Use a scoped key with a project budget. Only approved public comment text, scores, agent IDs and source issue numbers are sent, not authors, images or secrets. At least three nonempty reviews of the current version are required; at most 30 comments per skill and 20 API calls per build, no tools or storage requested. AI-generated text is labeled and validated against source issue numbers; it may still be imperfect and should be read alongside source reviews. Failed/disabled inference uses explicitly labeled statistics, never fake AI output. Do not enable this without accepting external API usage/cost and privacy terms.
- The approval label is provisioned by a separate least-privilege workflow on merge or manual dispatch. It never approves an Issue automatically.
- Run `node --test scripts/skill-ratings.test.mjs scripts/skill-insights.test.mjs` and `node scripts/build-skill-insights.mjs` for local verification; the latter uses the checked-in empty review snapshot when no real reviews are built. The empty snapshot is not published as a measured benchmark until the Pages build creates a timestamp.
