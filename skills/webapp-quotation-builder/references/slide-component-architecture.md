# โครงสร้างองค์ประกอบสไลด์ PPTX

อ่านร่วมกับ `slide-design-system.md` ก่อนสร้างหรือแก้สไลด์สำหรับลูกค้า ลำดับงานคือยืนยันข้อมูลใบเสนอราคา วางเนื้อหา เลือกองค์ประกอบ กำหนดกรอบ 16:9 สร้าง PPTX ส่งออก PDF และตรวจภาพกับข้อความ

ใช้ `scripts/slide_components.js` จัดโครงสร้างด้วย API, tokens, ระยะห่าง และ variants ขององค์ประกอบที่ใช้ซ้ำ สร้างข้อความและรูปทรงด้วย PptxGenJS โดยตรง งดภาพหน้าจอของ HTML และปุ่ม สวิตช์ หรือสถานะที่ทำให้เข้าใจว่าโต้ตอบใน PDF ได้

## องค์ประกอบ

| องค์ประกอบ | ข้อมูลและการจัดวาง |
|---|---|
| `Grid` | ข้อมูลระดับเดียวกัน 2–3 คอลัมน์ 1–2 แถว ช่องว่างเท่ากัน |
| `Stack` | ข้อมูลประกอบกัน วางแนวนอนหรือแนวตั้งและกำหนดอัตราส่วน |
| `HeroPanel` | ผลลัพธ์โครงการ บทสรุป และตัวอย่างกระบวนการ 3 ขั้น |
| `TotalBanner` | เน้นยอดรวมใต้การ์ดงวดชำระ |
| `MetricCard` | ป้ายกำกับ ตัวเลขพร้อมหน่วย และหมายเหตุเมื่อจำเป็น ใช้ 2–3 การ์ด |
| `FeatureCard` | ชื่อโมดูลสั้นและเลขลำดับ |
| `TextCard` | งานที่รวมและไม่รวม ใช้ข้อความกำกับสี |
| `Stepper` | ขั้นตอนที่ตกลงแล้ว 1–5 ขั้นต่อหน้า เส้นเชื่อมอยู่หลังวงกลม |
| `ProgressSegments` | สัดส่วนการจ่ายของแต่ละงวดรวม 100% |
| `PaymentCard` | ยอดเต็มทศนิยม เปอร์เซ็นต์ และเงื่อนไขชำระ สูงสุด 3 การ์ดต่อหน้า |
| `ServiceCard` | งานในและนอกประกันตามเงื่อนไขที่ยืนยันแล้ว |
| `Notice` | ป้ายและข้อความสำหรับเกณฑ์ตรวจรับ ส่งมอบ หรือข้อยกเว้น |
| `Diagram` | ผังงานและการเชื่อมต่อที่ยืนยันแล้ว 2–5 โหนด พร้อมทางแยกหรือวงย้อนเมื่อมี |
| `header` / `footer` | ป้ายภาษาไทย ชื่อเรื่อง เลขเอกสารและเลขหน้า |

ใช้ `HeroPanel` คู่กับ `MetricCard` ในภาพรวม ใช้ `Grid` และ `FeatureCard` แสดงขอบเขต และ `Stack` สำหรับสิ่งที่รวมและไม่รวม ใช้ `Stepper` คู่กับ `Notice` สำหรับแผนและเกณฑ์ตรวจรับ จัดงวดชำระด้วย `ProgressSegments`, `PaymentCard` และ `TotalBanner` ส่วนหลังการขายใช้ `ServiceCard` กับ `Notice` สำหรับค่าเปลี่ยนงานและสิทธิ์ในงาน

## การประกอบด้วย tree

ให้ไลบรารีคำนวณกรอบย่อยและค่ารูปทรงร่วมกัน เพิ่มองค์ประกอบใหม่ที่ registry ของ `SlideUI.render()` และนำไปใช้ซ้ำจาก `slide_components.js`

```js
const { SlideUI, tokens } = require('./slide_components');
const ui = new SlideUI(pptx, {
  logoPath: provider.logo_path,
  brand: provider.name, quoteId: quotation.number
});

// ขนาดหน้าคงที่ 13.333333 x 7.5 นิ้ว (16:9)
// ข้อความและยอดเงินด้านล่างใช้สาธิต API
ui.render(slide, {
  type: 'Grid', columns: 3, gapX: 0.20,
  children: [
    { type: 'MetricCard', label: 'TOTAL', value: '69,000.00 THB', tone: 'blue' },
    { type: 'MetricCard', label: 'DURATION', value: '8 weeks', tone: 'green' },
    { type: 'MetricCard', label: 'PAYMENTS', value: '3 stages', tone: 'amber' },
  ]
}, { x: 0.68, y: 4.70, w: 11.97, h: 1.51 });
```

ใช้ป้ายภาษาไทยและตัวเลขที่ยืนยันแล้วในสไลด์ลูกค้า

## Tokens และกรอบเนื้อหา

- ใช้ `canvas`, `space`, `type`, `color` และ `radius` จาก `slide_components.js`
- ระยะปลอดภัย 0.68 นิ้ว จุดเริ่มเนื้อหาประมาณ y=2.2 และส่วนท้ายประมาณ y=6.96 ใช้กริด 12 คอลัมน์เป็นแนวอ้างอิง วัดกรอบเป็นนิ้วและฟอนต์เป็น pt
- หัวเรื่อง 29–30 pt หัวการ์ด 18–20 pt เนื้อหา 17–19 pt ยอดสำคัญ 21–34 pt ป้ายย่อย 14–16 pt และส่วนท้าย 10 pt เผื่อความสูงสำหรับสระและวรรณยุกต์
- ใช้กรมท่าเน้นข้อมูล น้ำเงินสำหรับโครงสร้าง เขียวสำหรับงานที่รวม แดงหม่นสำหรับงานยกเว้น และอำพันสำหรับตัวเลือกหรือข้อสังเกต ใช้ข้อความช่วยสื่อความหมายทุกครั้ง
- คง 2–3 การ์ดต่อแถว แบ่งหน้าหากเนื้อหาแน่น โดยรักษาข้อความหลักอย่างน้อย 16 pt

## พฤติกรรมและกรณีข้อมูลผิด

- `Grid` และ `Stack` คำนวณกรอบแบบกำหนดผลได้และปฏิเสธขนาดผิด `SlideUI.render` ปฏิเสธชื่อองค์ประกอบที่ไม่รู้จัก `Diagram` ปฏิเสธ ID ที่หายหรือเส้นย้อนซับซ้อนเกินที่รองรับ
- ใช้ข้อมูลขอบเขต ระยะเวลา งวดชำระ การรับประกัน และตัวเลขจากใบเสนอราคาที่ได้รับการยืนยัน
- ข้อความและรูปทรงสำคัญแก้ไขได้ใน PPTX และข้อความไทยคัดลอกได้ใน PDF ใช้ภาพสำหรับโลโก้ที่ได้รับอนุญาตหรือภาพประกอบที่สร้างด้วยรูปทรงไม่ได้ หากผู้ใช้ขอ PPTX ให้ระบุองค์ประกอบที่แก้ไขไม่ได้
- รักษาหัวข้อหลัก 5 เรื่อง แบ่งได้ 5–12 หน้า หากเกินให้ปรับขอบเขตการนำเสนอหรือแก้ตัวสร้างโดยเก็บข้อมูลสำคัญครบ

## ทดสอบเมื่อแก้องค์ประกอบ

1. `node --check scripts/slide_components.js && node --check scripts/build_slides.js`
2. `python scripts/test_components.py` ตรวจ registry, layout และข้อความ PPTX
3. `python scripts/test_pricing.py` ตรวจการคำนวณ
4. `python scripts/test_slides.py` ตรวจตัวอย่าง 5 หน้า เนื้อหายาว 8 หน้า ขั้นตอนเดียว และ Flowchart
5. สร้างสไลด์ตัวอย่าง ใช้ `/home/oai/skills/slides/container_tools/slides_test.py` เมื่อมี แล้วส่งออก PDF และเรนเดอร์ PNG ทุกหน้า
6. ตรวจสระและวรรณยุกต์ ข้อความล้น ตัวเลขงวด ยอดรวม คอนทราสต์ ลำดับชั้น และเส้นเชื่อมจากภาพจริง
