# หลักฐานราคาและวิธีประเมินต้นทุน

## ตรวจแหล่งข้อมูลสำหรับใบเสนอราคาใหม่ทุกฉบับ

1. ค้นราคาที่ผู้ขายในไทยเผยแพร่สำหรับบริการใกล้เคียง บันทึกวันที่ตรวจ วันที่เผยแพร่หรือแก้ไขล่าสุด (ถ้าพบ) URL สกุลเงิน ขอบเขต VAT และข้อจำกัด เลือกข้อมูลที่ปรับใน 12 เดือนที่ผ่านมาเมื่อมี ระบุอายุของข้อมูลเก่าตามจริง สำหรับการเชื่อมต่อเฉพาะทางให้ตรวจราคา API/Cloud จากผู้ให้บริการโดยตรง
2. ใช้แหล่งอิสระอย่างน้อยสองแห่ง ให้ความสำคัญกับหน้าราคาจากผู้ขาย ตรวจว่าลิงก์ยังเปิดได้และราคายังแสดงอยู่ เรียกราคาเริ่มต้นตามที่แหล่งระบุ หากราคาต่างกันให้แสดงช่วงและอธิบายความต่างของขอบเขต
3. แยกเว็บองค์กร, CMS, ระบบจองหรือ Workflow, แอปภายในหลายบทบาท และงานองค์กรที่มีการเชื่อมต่อสูง ประเมินงานพัฒนาเฉพาะจากขอบเขตจริง
4. เติมข้อมูล วันที่ และลิงก์ในแบบฟอร์ม Markdown ก่อนให้ผู้เสนอราคากรอก ระบุรายการที่ยังตรวจไม่ได้ด้วย `ยังไม่ได้ยืนยัน`
5. เก็บหลักฐานใน `research.price_sources` ใช้ต้นทุนและเงื่อนไขของผู้เสนอราคาในเอกสารลูกค้า

## แหล่งข้อมูลที่ใช้ในตัวอย่าง (ตรวจซ้ำก่อนใช้)

- Bluewich อัปเดตบทความ 2026-11-04 ระบุราคาเริ่มต้น 25,000 THB สำหรับเว็บธุรกิจเฉพาะ และ 50,000 THB สำหรับระบบจองหรือสั่งซื้อ https://bluewich.com/blog/website-cost-bangkok-2026/
- FAQ ของ OPEN / Studio ระบุ 90,000 THB สำหรับเว็บ Interactive, 135,000 THB สำหรับระบบภายใน และ 180,000 THB สำหรับ Customer Portal/CRM/SaaS https://openstudio.asia/faqs
- Digital Agency Bangkok ระบุช่วงราคา Web App เฉพาะประมาณ 150,000–500,000 THB ในข้อมูลปี 2026 https://digitalagencybangkok.com/how-much-does-a-website-cost-in-thailand-2026/
- Vectorkub วันที่ 2026-11-02 ประมาณราคา 150,000+ THB สำหรับแอปที่มีการเข้าสู่ระบบ การชำระเงิน หรือการเชื่อมต่อ https://vectorkub.com/en/articles/website-development-cost-thailand

แหล่งเหล่านี้เป็นข้อมูลการตลาดจากผู้ขาย ใช้อ้างอิงช่วงราคาเบื้องต้น

## ประมาณต้นทุนภายใน

1. แยกงานออกแบบ Backend Frontend การเชื่อมต่อ QA การติดตั้ง เอกสาร/อบรม และค่าเผื่อประกัน ประเมินวันทำงานแบบดีที่สุด ฐาน และกรณีล่าช้า โดยพิจารณาจำนวนฟีเจอร์ สิทธิ์และลำดับอนุมัติ การย้ายข้อมูล การเชื่อมต่อ และเกณฑ์ตรวจรับ
2. ค่าทำงานโดยตรง = จำนวนวัน × ต้นทุนจริงต่อวัน เพิ่มค่าเครื่องมือ ลิขสิทธิ์ โฮสติ้ง ค่าใช้จ่ายดำเนินงาน และค่าเผื่อ
3. ถ้ากำหนด gross margin เป็น M เช่น 0.30 ให้ใช้ราคาก่อนภาษี = ต้นทุนรวม / (1 - M) โดย 0 <= M < 1 ใช้ต้นทุน × (1 + M) เฉพาะเมื่อผู้ใช้กำหนด markup
4. เทียบราคาเฉพาะขอบเขตใกล้เคียงและเทียบงบลูกค้า อธิบายส่วนต่างและเสนอ MVP หรือแบ่งระยะเมื่องบต่ำกว่าต้นทุนที่ทำได้จริง
5. คำนวณจำนวน × ราคาต่อหน่วย แสดงส่วนลดชัดเจน ปัดสตางค์ด้วย decimal HALF_UP คิด VAT เฉพาะผู้จดทะเบียนตามอัตราที่ตรวจสอบแล้ว รวมงวดชำระให้เท่ากับ 100% และปรับเศษจากการปัดที่งวดสุดท้าย
6. กรณีความไม่แน่นอนสูง ประเมินสามทางเลือกภายในตามขอบเขตขั้นต่ำ แนะนำ และเพิ่มเติม แล้วออกเอกสารลูกค้าตามตัวเลือกที่ยืนยันหนึ่งรายการ
7. ระบุสมมติฐาน การอนุมัติจากผู้เกี่ยวข้อง และเงื่อนไข Change Request สำหรับข้อมูล การย้ายระบบ หรือ API ที่ยังไม่ยืนยัน เก็บต้นทุนและกำไรไว้ภายใน

## กรณีเฉพาะ

- งานจัดซื้อภาครัฐ ใช้ TOR และกฎภาษี/การเสนอราคาของหน่วยงาน และยืนยันข้อกำหนดเฉพาะก่อนอ้างความสอดคล้อง
- รายละเอียดยังไม่พอ ให้ระบุว่าเป็นข้อเสนอสำรวจแบบมีค่าใช้จ่ายหรืองบประมาณเบื้องต้น
- งบต่ำมาก ให้แบ่ง MVP โดยแจ้งผลต่อขอบเขต ความปลอดภัย การสำรองข้อมูล QA และการคุ้มครองข้อมูล
- ผู้เสนอราคาที่ไม่ได้จด VAT ให้ใช้ข้อความ ‘ไม่คิด VAT (ผู้เสนอราคาไม่ได้จดทะเบียน VAT)’ และเว้นบรรทัดภาษี
