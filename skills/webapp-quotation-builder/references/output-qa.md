# การจัดหน้าและตรวจคุณภาพ

## PDF 1 ใบเสนอราคา

- ชื่อ `quotation-<quote-id>.pdf` ขนาด A4 210×297 mm แนวตั้งหนึ่งหน้า
- ใช้พื้นขาว ตัวอักษรเข้ม สีเน้นหนึ่งสี ฟอนต์ไทยที่อ่านได้ โลโก้จริงเมื่อมี และลำดับตัวอักษรสามระดับที่ยังอ่านหมายเหตุได้
- ส่วนบนใส่ผู้เสนอราคา `ใบเสนอราคา / QUOTATION` เลขที่ วันออกและวันหมดอายุ
- แสดงชื่อ ที่อยู่และผู้ติดต่อของลูกค้า ชื่อโครงการ และผลลัพธ์ที่คาดหวังแบบย่อ
- จัด 3–7 กลุ่มงาน ระบุจำนวน หน่วย ราคาต่อหน่วย ยอดรายการ ยอดก่อนลด ส่วนลด VAT ตามกรณี และยอดรวม
- ส่วนท้ายแสดงงวดชำระ เงื่อนไขแต่ละงวด ระยะเวลา ตรวจรับ การแก้ไข สิทธิ์ ส่งมอบ ประกัน ข้อยกเว้น ค่าใช้จ่ายภายนอก และช่องอนุมัติ กำกับ ‘ตัวอย่าง’ เมื่อใช้ข้อมูลสมมติ
- ใส่ **ใบเสนอราคา ไม่ใช่ใบกำกับภาษี** และใช้คำเรียกใบเสนอราคาในส่วนอื่น
- หากเนื้อหาแน่น ให้จัดกลุ่มและย่อข้อความ ย้ายรายละเอียดประกอบไปสไลด์หรือ SOW พร้อมอ้างข้ามเอกสาร รักษาขอบเขตและข้อสัญญาสำคัญให้อ่านได้ครบ

## PDF 2 สไลด์สำหรับลูกค้า

- ชื่อ `service-overview-<quote-id>.pdf` ขนาด 16:9 แนวนอน ปกติ 5 หน้า ขยายได้ถึง 12 หน้าเมื่อเนื้อหาจำเป็น
- หน้า 1 เป้าหมาย ผลลัพธ์ ยอดเสนอราคา ระยะเวลา และคุณค่าหลัก 3 ข้อ
- หน้า 2 งานส่งมอบ จัดกลุ่มงานที่รวมและไม่รวม
- หน้า 3 แผนตามลำดับตั้งแต่สำรวจ/ออกแบบ พัฒนา QA/UAT จนติดตั้งและอบรม ใช้ระยะเวลาที่ตกลงแล้ว
- หน้า 4 งวดชำระพร้อมเปอร์เซ็นต์ ยอด THB งานส่งมอบและเงื่อนไขอนุมัติ รวมยอดให้ตรงกับยอดเสนอราคา
- หน้า 5 ตารางงานในประกัน งานนอกประกัน งานเพิ่มเติมหรือค่าบำรุงรักษา สิทธิ์ ส่งต่องาน และขั้นตอนถัดไป
- หนึ่งประเด็นต่อหน้า ใช้ตัวอักษร 16–34 pt เมื่อทำได้ เว้นระยะ มีคอนทราสต์ และใช้แผนภาพเมื่ออธิบายง่ายกว่า เก็บต้นทุนแรงงานและกำไรขั้นต้นไว้ภายใน
- ใช้ชื่อโครงการ ลูกค้า เลขที่ ราคา งวดชำระ เงื่อนไข และวันหมดอายุที่ตรงกับใบเสนอราคา

## ขั้นตอนตรวจ

1. ตรวจ schema ยอดรายการเป็นบวก VAT ชัดเจน วันออก/หมดอายุ งวดรวม 100% (ยกเว้นกรณีตกลงไม่มีงวด) และไม่มี `TBD` หรือข้อความตัวอย่างในเอกสารจริง
2. ใช้ Python `decimal` สองตำแหน่ง ยอดรวม = ยอดก่อนลด - ส่วนลด + VAT ยอดงวดรวมต้องตรงกัน สำหรับผู้ไม่จดทะเบียนให้ VAT เป็น 0 และเว้นบรรทัดภาษีในเอกสาร
3. สร้าง HTML และพิมพ์ PDF ด้วย Chromium และฟอนต์ไทย ใช้ PyMuPDF ตรวจว่ามีหนึ่งหน้า ขนาด A4 ตาม tolerance พบหัวเอกสารและยอดที่คาด
4. สร้าง PPTX ด้วย PptxGenJS ส่งออกด้วย LibreOffice และตรวจด้วย `scripts/slide_preflight.py` ว่าแนวนอนใกล้ 16:9 จำนวน 5–12 หน้า มีขอบเขตงาน ขั้นตอน งวดชำระ และยอดรวมครบ
5. เรนเดอร์ PNG ด้วย `pdftoppm` หรือ PyMuPDF ตรวจการตัดบรรทัด ข้อความล้น โลโก้ และระยะจากขอบ แก้แล้วรันซ้ำเมื่อพบปัญหา
6. เทียบ `grand_total` และงวดชำระในสองเอกสาร ตรวจทรัพยากรและ glyph ภาษาไทยให้ครบ
7. เอกสารสาธิตต้องเห็นข้อความ ‘ข้อมูลสมมติ — ตัวอย่างเท่านั้น’ ชัดเจน
