# ระบบออกแบบสไลด์ข้อเสนอภาษาไทย

ใช้ก่อนจัดทำ `service-overview-*.pdf` รักษาขอบเขต กำหนดการ ค่าบริการ และประกันตามข้อมูลที่ลูกค้ายืนยัน

## ลำดับเนื้อหา

| หน้า | คำถามลูกค้า | การจัดวาง |
|---|---|---|
| ภาพรวม | โครงการนี้ช่วยอะไร | สรุปผลลัพธ์และ 2–3 KPI เช่น ยอดรวมและระยะเวลา |
| ขอบเขต | จะได้รับส่วนใด | Grid ของโมดูล พร้อมสิ่งที่รวมและข้อยกเว้น |
| แผนงาน | ทำงานและตรวจรับอย่างไร | Stepper แสดงช่วงเวลาที่ตกลงและเกณฑ์ UAT |
| งวดชำระ | จ่ายเท่าไรและเมื่อใด | การ์ดแสดง % ยอด THB เงื่อนไขชำระ และยอดรวม |
| หลังส่งมอบ | ได้รับการดูแลอย่างไร | เงื่อนไขประกัน งานยกเว้น ค่าเปลี่ยนงาน และสิทธิ์ในซอร์สโค้ด |

ใช้ 5 หน้าตามปกติ แบ่งหน้าต่อได้ถึง 12 หน้า หน้าภาพรวมต้องสื่อบริบทโครงการและทุกหน้าตอบคำถามหลักหนึ่งข้อ

## กรอบและตัวอักษร

- ใช้ `LAYOUT_WIDE` 16:9 ขนาด 13.3333 × 7.5 นิ้ว ระยะปลอดภัยแนวนอน 0.65–0.75 นิ้ว แนวตั้ง 0.45–0.55 นิ้ว กันส่วนท้าย 0.26 นิ้ว
- วางกริด 12 คอลัมน์ในความกว้าง 11.9–12.0 นิ้ว ช่อง 0.20–0.24 นิ้ว ใช้ระยะเพิ่ม 0.08/0.16/0.24/0.32 นิ้ว จัดหัวเรื่อง การ์ด และยอดตามแนวเดียวกัน
- แถวบริบท y=0.48–0.88 หัวเรื่อง y=0.96–1.49 คำอธิบายบรรทัดเดียว y=1.63–2.0 เนื้อหาหลัก y=2.16–6.65 ส่วนท้าย y≈7.1
- ใช้ `Sarabun` กับข้อความทุกส่วนของสไลด์ และตรวจว่า PDF ฝังฟอนต์ `Sarabun` ก่อนส่งมอบ
- ขนาด pt สำหรับชื่อโครงการ 30–38 หัวสไลด์ 27–32 ตัวเลขสำคัญ 26–34 หัวการ์ด/ขั้น 18–21 เนื้อหา 17–20 เป้าหมาย 18+ หมายเหตุ 14–16 และส่วนท้าย 10–11 สำหรับโปรเจกเตอร์ให้ตั้งเป้าเนื้อหา 20–24 โดยเนื้อหาหลักต้องอย่างน้อย 16 pt
- ใช้น้ำหนักตัวอักษรช่วยเน้น ระยะบรรทัดประมาณ 1.2–1.35 เลี่ยงฟอนต์แคบ เผื่อที่ให้สระและวรรณยุกต์ ใช้ชื่อโมดูลไม่เกิน 24 อักษรหรือสองบรรทัดเมื่อทำได้
- จัดข้อความไทยชิดซ้าย ยอดรวมชิดขวา และเลขลำดับกึ่งกลาง เว้นขอบในกล่อง 0.18–0.24 นิ้ว ลำดับการอ่านซ้ายไปขวาและบนลงล่าง

## การใช้ภาษา

ใช้หัวเรื่อง ป้าย และคำอธิบายภาษาไทย คงชื่อเฉพาะและคำย่อเทคนิค ตรวจชื่อเงื่อนไขตามที่ตกลง คำย่อใช้รูปแบบ `คำไทย (Technical Term)` ตอนกล่าวครั้งแรกได้

| คำต้นทาง | ป้ายสไลด์ภาษาไทย |
|---|---|
| Proposal overview | ภาพรวมโครงการ |
| Included scope | ขอบเขตงานที่ได้รับ |
| Delivery roadmap | แผนดำเนินงานและการส่งมอบ |
| Milestone payments | การชำระเงินตามงวดงาน |
| Support & ownership | การดูแลหลังส่งมอบและสิทธิในงาน |
| STEP 01 | ขั้นที่ 1 |
| Go-live | เริ่มใช้งานจริง (Go-Live) |
| Demo | ระบบตัวอย่าง (Demo) |
| UAT | ทดสอบรับมอบ (UAT) |
| Deploy | ติดตั้งระบบ (Deploy) |
| Change Request | คำขอเปลี่ยนแปลงงาน (Change Request) |
| Hosting / Domain | ค่าเซิร์ฟเวอร์ (Hosting) / โดเมน (Domain) |
| Source Code | ซอร์สโค้ด (Source Code) |

- แสดงยอดด้วยเลขอารบิกและคั่นหลักพัน เช่น `69,000.00 บาท` ใช้ VAT ตามสถานะที่ตรวจแล้ว และใช้ข้อความ `รวม VAT` หรือ `ไม่คิด VAT ตามสถานะผู้ขาย` ตามจริง
- ใช้ป้ายที่สื่อเงื่อนไข เช่น `งวดที่ 1 — ยืนยันขอบเขต` และรักษาข้อความที่มีผลต่อสัญญาเมื่อแปลหรือย่อ ย้ายไปหน้าต่อเมื่อเนื้อหายาว
- ตรวจคำว่า `ส่งมอบ`, `ตรวจรับ`, `รับประกัน`, `ค่าดูแลรายเดือน`, `นอกขอบเขต`, `ภาษีมูลค่าเพิ่ม` ตามหน้าที่ของแต่ละส่วน

## แผนภาพและความชัดเจน

- เลือกภาพหลักหนึ่งอย่าง ต่อเนื่องใช้ Stepper ตัดสินใจใช้ Flowchart เชื่อมระบบใช้แผนภาพโหนด กำหนดการใช้ Timeline งวดชำระใช้การ์ดและแถบสัดส่วน ขอบเขตใช้ Grid
- ใช้กรมท่ากับหัวเรื่อง น้ำเงินกับข้อมูลหลัก เขียวกับสิ่งที่รวม อำพันกับทางเลือก แดงหม่นกับงานยกเว้น หรือมีค่าเพิ่ม ใช้ป้ายและหน่วยกำกับตัวเลขและสี
- ใช้ W3C WCAG 2.2 ข้อ 1.4.3 เป็นเป้าหมายออกแบบ คอนทราสต์อย่างน้อย 4.5:1 สำหรับตัวอักษรทั่วไปและ 3:1 สำหรับตัวอักษรใหญ่
- ใช้รูปทรงและเส้น PPTX ที่แก้ไขได้ ลดเงาหนา พื้นที่ตกแต่ง และภาพที่กินพื้นที่เงื่อนไขการค้า

## การแบ่งหน้าและตรวจผล

- ภาพรวมใช้ชื่อประมาณไม่เกิน 60 ตัวอักษรหรือ 2 บรรทัด บทสรุปประมาณ 120 ตัวอักษร และ 3 KPI
- จำกัด 6 โมดูล, 5 ขั้นตอน หรือ 3 งวดต่อหน้า ใช้หัวข้อหน้าต่อและเลขลำดับต่อเนื่อง แสดงยอดรวมในหน้างวดชำระทุกหน้า
- จัดบริการหลังการขายเป็นประกัน ข้อยกเว้น และบริการมีค่าใช้จ่าย แยกหน้าสิทธิ์ซอร์สโค้ดเมื่อข้อความยาว
- หากล้นให้ย่อคำซ้ำ ขยายช่องหรือจัดแนวใหม่ แบ่งหน้า หรือเพิ่มพื้นที่เนื้อหา ก่อนลดขนาดตัวอักษรภายในเกณฑ์ คงข้อความ Unicode ที่ค้นหาได้ใน PDF
- ตรวจทุกหน้าที่ขนาดจริงบนจอ 1366–1920 px และภาพย่อ 25% ให้ตอบคำถามหลักได้ใน 5–10 วินาที ตรวจยอด กำหนดการ ชื่อ ข้อความไทย ข้อสัญญา กรอบ คอนทราสต์ และเส้นเชื่อม
