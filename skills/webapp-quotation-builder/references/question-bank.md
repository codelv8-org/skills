# ชุดคำถามเก็บขอบเขตภาษาไทย พร้อมอย่างน้อย 3 ตัวเลือกและ Other ทุกข้อ

**ถามครั้งละ 2–4 ข้อ** ให้ตัวเลือก A/B/C พร้อม `Other: [ระบุเอง]` ทุกข้อ เพิ่ม D “ยังไม่แน่ใจ” ได้เมื่อเหมาะสม ข้ามข้อที่ตอบแล้วหรือไม่เกี่ยวข้อง หากผู้ใช้ส่งบรีฟมา ให้สรุปสิ่งที่เข้าใจและขอให้ยืนยันเฉพาะประเด็นสำคัญด้วยตัวเลือกอย่างน้อย 3 ข้อพร้อม Other

## ชุด A แนวทางโครงการ (ทุกโครงการ)

**Q1. ทำระบบแบบไหน?** A เว็บแอปภายในองค์กร / B เว็บแอปบริการลูกค้า / C PWA เน้นมือถือ / Other: ______

**Q2. เป้าหมายหลักของระบบ?** A ลดงานเอกสารและ Workflow / B ระบบจองคิว/จองบริการ / C ระบบจัดการข้อมูลและรายงาน / Other: ______

**Q3. ใครเป็นผู้ใช้ระบบ?** A เจ้าหน้าที่ภายใน / B ลูกค้าภายนอก / C ทั้งเจ้าหน้าที่และลูกค้า / Other: ______

**Q4. ขนาดผู้ใช้งานประมาณเท่าไร?** A < 50 คน / B 50–500 คน / C > 500 คน หรือหลายองค์กร / Other: ______

## ชุด B ขอบเขตฟังก์ชัน (เลือกหลายข้อได้ตามความเหมาะสม)

**Q5. ฟีเจอร์หลักที่ต้องมี? (เลือกหลายข้อได้)** A เข้าสู่ระบบ/สิทธิ์/โปรไฟล์ / B แบบฟอร์ม/อนุมัติ/สถานะ / C Dashboard/รายงาน/ส่งออกไฟล์ / Other: [ระบุฟีเจอร์, จำนวนหน้าหรือโมดูล] ______

**Q6. ระดับ UI/UX?** A ใช้ Design System/Template ที่ปรับแต่ง / B ออกแบบ UI เฉพาะแบรนด์ / C ออกแบบเฉพาะพร้อม Prototype และ Responsive / Other: ______

**Q7. ข้อมูลเริ่มต้น?** A ฐานข้อมูลใหม่ / B นำเข้า Excel/CSV / C ย้ายจากระบบเดิมหรือฐานข้อมูลอื่น / Other: ______

**Q8. เชื่อมต่อภายนอกหรือไม่?** A ไม่เชื่อมต่อ / B LINE/Email/ชำระเงิน/แผนที่ (ระบุ) / C HIS/ERP/SSO/AD/API ภายในองค์กร (ระบุ) / Other: ______

## ชุด C ความเสี่ยงในการส่งมอบ

**Q9. ข้อมูลความอ่อนไหว?** A ข้อมูลธุรกิจทั่วไป / B ข้อมูลบุคคลทั่วไป / C ข้อมูลสุขภาพ/การเงิน/อ่อนไหวต้องควบคุมพิเศษ / Other: ______

**Q10. ระบบจะ Deploy ที่ใด?** A Hosting/Cloud ผู้ให้บริการจัดให้ / B Server ลูกค้าหรือ On-Premise / C ยังไม่ทราบ ต้องช่วยเสนอทางเลือก / Other: ______

**Q11. กรอบเวลาที่ต้องการ?** A ไม่เร่ง เลือกกำหนดตาม Scope / B ภายใน 4–8 สัปดาห์ / C ภายใน 1–4 สัปดาห์ (ต้องประเมินความเป็นไปได้) / Other: [วันเริ่ม/วันส่ง] ______

**Q12. งบประมาณที่คาดหวัง?** A ต่ำกว่า 50,000 บาท / B 50,000–150,000 บาท / C มากกว่า 150,000 บาท / Other: [ตัวเลขหรือเงื่อนไข] ______

## ชุด D เงื่อนไขและการส่งมอบ (ข้ามได้เมื่อยืนยันในโปรไฟล์และโครงการใช้ค่าเดิม)

**Q13. ผลงานที่ต้องส่งมอบ?** A ระบบพร้อมใช้งาน + คู่มือ / B ระบบ + Source Code/Repository + คู่มือ / C ระบบ + Code + Training + ส่งต่อดูแล / Other: ______

**Q14. รูปแบบการรับงาน/UAT?** A Review 1–2 รอบ + ยืนยัน Acceptance / B ตาม Checklist Test Case/Performance / C ทดสอบกับผู้ใช้จริงเป็น Pilot ก่อนรับมอบ / Other: ______

**Q15. งวดชำระเงิน?** A 30/40/30 เริ่ม/Demo+UAT/รับมอบ / B 50/50 เริ่ม/รับมอบ / C 40/30/30 เริ่ม/Beta/รับมอบ / Other: [งวด+เหตุการณ์] ______

**Q16. บริการหลังส่งมอบ?** A รับประกันแก้บั๊กตาม Scope / B รับประกัน + บำรุงรักษารายเดือน / C SLA และบริการดูแลต่อเนื่อง / Other: ______

**Q17. งานเพิ่มเติมหลังยืนยัน Scope?** A คิดรายชั่วโมงตาม Rate / B ตีราคา Change Request แยกงาน / C เลือก Support Package/Retainer / Other: ______

## ชุด E ข้อมูลลูกค้าและเงื่อนไขการค้า (ต้องครบก่อนสร้างเอกสาร)

**Q18. ผู้รับใบเสนอราคาเป็นใคร?** A บริษัท/หจก. ในไทย [กรอกชื่อ-ที่อยู่-ผู้ติดต่อ] / B บุคคลธรรมดา/ร้านค้า [กรอกชื่อ-ที่อยู่-ผู้ติดต่อ] / C หน่วยงานรัฐ/สถาบัน [กรอกชื่อ-ที่อยู่-ผู้ติดต่อ] / Other: [ประเภทอื่นและชื่อ-ที่อยู่-ผู้ติดต่อ] ______. **ต้องกรอกชื่อจริงสำหรับออกเอกสาร ที่อยู่เรียกเก็บเงิน และผู้ติดต่อลูกค้าควบคู่กับประเภทที่เลือก**

**Q19. ภาษี/การชำระเงินฝั่งลูกค้า?** A หน่วยงานไทยที่อาจมี WHT / B บุคคลทั่วไป (ตรวจสอบ WHT ตามจริง) / C ต่างประเทศหรือข้ามแดน (ต้องประเมินแยก) / Other: ______

**Q20. การอนุมัติ/อำนาจลงนาม?** A ลูกค้ารับข้อเสนอผ่านลงชื่อ / B ลูกค้ามีเอกสาร PO/สัญญาจ้างแยก / C อนุมัติผ่านอีเมลก่อนจัดทำสัญญา / Other: ______

## คำถามต่อยอดตามขอบเขต

**เมื่อมีหลายบทบาทหรือ SSO** เลือก A เข้าด้วยอีเมล / B AD/LDAP/SSO / C ThaiD/OIDC/ผู้ให้บริการภายนอก / Other ______ ถามจำนวนบทบาทและระดับการอนุมัติเพิ่มเติม

**เมื่อต้องย้ายข้อมูล** เลือก A CSV ≤ 5,000 รายการ / B ฐานข้อมูลเดิมที่ทราบ schema / C ฐานข้อมูลเดิมที่ยังไม่ทราบโครงสร้างหรือต้องทำความสะอาด / Other ______ ถามปริมาณ คุณภาพ และวิธีเข้าถึง

**เมื่อเชื่อม API ภายนอก** เลือก A API พร้อมเอกสาร / B มี API แต่ยังไม่เสถียรหรือมีข้อจำกัด / C ต้องพัฒนาหรือเจรจาขอใช้ API / Other ______ ถามข้อมูล sandbox และผู้รับผิดชอบ โดยเว้น token และ secret

**เมื่อเกี่ยวกับข้อมูลสุขภาพหรืองานความเสี่ยงสูง** เลือก A ข้อมูลที่ไม่สามารถระบุตัวบุคคล / B ข้อมูลบุคคลหรือข้อมูลคลินิกที่ระบุตัวได้ / C ข้อมูลผสมและเชื่อมหลายระบบ / Other ______ ถามการกำกับข้อมูล สิทธิ์เข้าใช้ การเก็บ log การตรวจสอบ และการสำรองข้อมูล ยืนยันการปฏิบัติตามข้อกำหนดหลังผ่านการทบทวน

**เมื่อใช้ AI** เลือก A API ผู้ให้บริการเดิม / B โมเดลในเครื่องหรือ On-Prem / C แบบผสม / Other ______ ตกลงต้นทุน token/compute และความเป็นส่วนตัวของข้อมูล

**เมื่อเวลาจำกัด** เลือก A ทำเฉพาะฟีเจอร์หลักของ MVP / B นำขึ้นใช้งานจริงหลัง Pilot / C ขยายเวลาเพื่อทำครบขอบเขต / Other ______

**เมื่อจำนวนโมดูลยังไม่ชัด** เลือก A <5 / B 5–10 / C >10 / Other ระบุโมดูลเอง

## ตรวจความครบถ้วนก่อนสร้างเอกสาร

ก่อนสร้างเอกสาร สรุปขอบเขตที่ยืนยัน งานนอกขอบเขต ประเภทข้อเสนอ (ราคาคงที่หรือประมาณการ) ข้อมูลลูกค้า การส่งมอบ งวดชำระ และต้นทุนที่ทราบ ขอข้อมูลเพิ่มเฉพาะส่วนสำคัญที่ยังขาด
