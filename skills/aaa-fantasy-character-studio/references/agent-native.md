# Agent-native production contract

## Modes and hard boundaries
- STRICT_AGENT_CLOUD (default): only selected AI model plus the agent platform's verified hosted Python/code execution, filesystem and optional first-party vision/render tools. No Meshy/Tripo calls, third-party model downloads, credentials, uploads, additional service or local machine execution. Use standard library native compiler or author project-specific algorithms. Do not invoke unapproved tools. Use existing user-supplied assets only with rights and scope.
- CLOUD_DCC: optional explicit user opt-in to a DCC or preinstalled geometry libraries on the platform-hosted runtime. No separately hosted service or external generation unless separately authorized. Inspect versions. Do not install packages or download weights silently.
- PLAN_ONLY: no verified hosted execution; provide source and commands, clearly label BLOCKED. Never pretend a textual GLB manifest or generated image is a rendered mesh.
- A browser on a user's device consumes compute when displaying a GLB. Zero local compute means generation, not viewing/downloading/gameplay. Record cloud generation vs target-device checks separately.

Model minimum is a user preference: Gemini 4 Hydrogen or stronger, GPT-6 Sol or stronger, Claude Opus 5.5 or stronger, or explicitly accepted equivalent. Check actual provider model and available tool execution. Never infer exact model, compare tiers across vendors by name, claim access to other models, or dispatch them without authorization. Model-only inference produces code/IR; geometry execution is indispensable. Use high reasoning for complex sculpt code and visual discrepancy diagnosis when supported. Do not promise GPU, independent reviewer, image generator, runtime persistence or cost-free usage.

## Capability routing
1. Confirm platform-hosted runtime and writable artifact path; run preflight, record versions, time/memory limits and available evidence tools. Set bounded CPU, triangle/texture/iteration budgets and checkpoint after each part. Never start unbounded dense volumetric grids. If the platform exposes independent subagents, use same allowed model family for reviewer; otherwise require independent human review and mark REVIEW_REQUIRED.
2. G0: convert text/reference to semantic character spec; preserve input view provenance. Use actual front/back/left/right with matched camera if available; inferred views are hypotheses, not observed geometry. Record landmark positions, confidence and target dimensions. Do not invent depth accuracy from single images.
3. G1-4: design part graph with IDs, material, joints, anchors, visibility, dependencies. Build coherent anatomical surfaces using agent-authored cross-section lofts, explicit quad patches, fitted spline surfaces, adaptive subdivision or bounded implicit surfaces with extraction when actually implemented. Prefer continuous topology around face and joints; avoid a primitive assembly. Build fitted cloth panels, thickness, layered folds, swept hair clumps and ornaments with modular interfaces. Preserve original sources and high-resolution candidate. Generate geometry in actual runtime, obtain actual neutral views (native `render_clay.py` provides bounded CPU bind-pose diagnostic renders from exact GLB); lock camera with `--camera-from` for native revision views; compare reference and candidate, repair specific part with stable boundaries. Do not claim learned reconstruction from these algorithms.
4. G5-6: author runtime topology alongside surface construction (not merely decimation). Separate high/low with named parts; preserve edge loops and consistent winding. Agent authors seams and UV islands; test checker, overlaps and texel density. Native compiler accepts explicit quads/triangles or ring lofts; it triangulates for GLB but does not perform automated retopology, subdivision, collision detection or general UV unwrap. For these use agent-authored and tested algorithms or authorized backend. Do not mark these gates PASS just because compiler runs.
5. G7-8: bake maps using actual high/low ray tests with tangent space, if implemented; otherwise mark bake NOT RUN. Procedural material parameters and authored maps are distinct from measured normal/AO bakes. If renderer or first-party image tools exist, use them only as scoped (image generation for concept/albedo, not geometry or evidence). Native exporter embeds supplied PNG/JPEG PBR maps; material factors alone do not imply PBR texture set. Inspect actual renders.
6. G9: derive skeleton from anatomical landmarks; assign explicit normalized weights to vertices and preserve hair/cloth chains. Native compiler supports translation-only bind joints with authored weights and explicit rotation/translation animation tracks; no automatic skinning, IK or simulation. Test deformed output. Generate additional rig/clip scripts as needed. If not implemented, explicitly scope and mark NOT RUN.
7. G10-11: GLB export, editable source IR and code, actual reimport and full validator where available, exact candidate review, gates. User target device cannot be benchmarked in the cloud by inference; run actual cloud engine tests and distinguish from target-device evidence. Return actual outputs with hashes and statuses. Do not claim AAA equivalence to specialized neural generators or label production-ready without all gates and independent review.

## Local edit and checkpoints
Store parts with stable IDs, seam anchors, parent bones and material contracts. Use separate immutable revision files, never overwrite accepted inputs. For targeted edit, update one part and regenerate affected dependencies (UV, bake, weight, animation, export); hash unaffected part source and verify unchanged. Reuse accepted geometry; avoid re-generating full character. Keep per-part triangle counts, errors, view comparisons and measured constraints. Re-run affected gates and all descendants. Limit iterations to explicit budget; stop at earliest unresolved critical defect and deliver honest PROTOTYPE/REVIEW_REQUIRED/BLOCKED. The native fixture is for compiler QA only, never a character benchmark.
