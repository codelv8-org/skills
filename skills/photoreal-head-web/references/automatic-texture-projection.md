# Automatic texture projection (v3.1)

## Contract and limits

This CPU pipeline converts calibrated, authorized RGB views into observed surface color on the actual locked GLB UV0. It is not a neural face generator, landmark detector, scanner, inverse renderer, or intrinsic albedo estimator. Fit geometry first; do not use texture warping to conceal anatomy errors. Run in a clean output directory, keep sources and reports local, never publish photos or face textures without rights. With no Blender available, the tools still run on decoded static GLB. Source mesh must be meters, rest/neutral pose, glTF world coordinates (+Y up), one unique opaque skin material, no transformed UV texture, no morph/skin/compression. Eyes/hair opaque geometry occlude skin; alpha-masked/blended geometry is skipped and MUST be manually excluded from every photo mask. Keep brows off the neutral base if overlays are needed.

## Acquire and register

- Prefer calibrated front, both 45-degree, profiles, back, elevated and lower views with fixed lens/exposure/white balance, neutral expression, sharp diffuse or cross-polarized lighting. Use a color chart if possible. Avoid beauty filters, mirroring, perspective mismatch, makeup if creating neutral skin, cropped camera intrinsics and changing expressions. Reserve 2+ independently captured oblique views as holdout BEFORE fitting texture, never train on holdout, crops or duplicates.
- Rectify lens distortion and every associated mask/landmark consistently using OpenCV `undistort` or `initUndistortRectifyMap`; update K after crop/resize. Record pixel center convention, calibration provenance and masks. EXIF focal length alone does not calibrate a camera. Manual rectification and calibration are not automated by this script.
- For each view supply `K`, `R`, `t` from camera calibration/photogrammetry (world-to-camera OpenCV +X right, +Y down, +Z forward, `q=R @ p + t`, translation meters), or provide K and independently annotated 3D mesh/2D image point pairs. Use >=6 noncoplanar fit anchors and >=3 different held-out validation anchors; RANSAC + LM estimates pose and rejects held-out RMS above the configurable starting 3px threshold. Choose project threshold at actual image size. Inspect overlay against brows, nose, ears, lips, hairline and silhouette; flag camera/shape ambiguity. Do not fabricate anchor positions. Explicit R/t still needs independent overlay inspection. If one image only, never claim full head coverage.
- Prepare per-view binary mask (white = trusted visible skin). Exclude hair, eyes, teeth, eyelashes, glasses, eyebrows if neutral brow, specular, cast shadows, motion blur and occluders. Keep actual lips only when intended. Do not use whole face detector box. Images and masks must have identical rectified dimensions. All pixels are treated as sRGB; convert RAW/ICC to sRGB first.

## Run

Install in an ordinary Python environment, not Blender Python: `python -m pip install -r scripts/requirements-projection.txt`. Start at 512 or 1024 square; 2K+ uses more RAM and 4K needs substantial memory; measure and choose device budgets. NumPy/Numba CPU rasterizer uses explicit perspective correction and does not support near-plane clipping or distorted/moving geometry.

1. Run v3 `validate_head_surface.py head.draft.glb --skin-material Skin --winding cw --uv-only --report-dir reports/uv` (choose actual winding). Correct failures, re-export, revalidate and hash exact draft GLB. `diagnostic_mode:true` is allowed only for investigation, never bypass G4 or promote output.
2. Fill `assets/templates/projection_manifest.json` with actual mesh hash, report path, material, privacy/license provenance, cameras and masks. Paths relative to manifest or absolute; don't include private manifests in a public repository. Set pose review only after inspection. For test data use `source_kind:rendered_asset`, not `real_photo`. `linear_gain` optionally adjusts measured exposure/white balance. Optional `exposure_match:overlap_scalar` estimates a robust scalar in linear light from sufficiently supported overlapping texels (>=128 unsaturated samples), clamps gain to [0.67,1.5] relative to earlier views, logs overlap and gain. Put the most trustworthy view first; it is order-dependent, not full color calibration or delighting. If insufficient overlap, inspect; no automatic gain is applied.
3. `python scripts/project_face_texture.py inputs/projection.json --out reports/projection --size 1024`. Rasterize UV0 into 3D surface points; project calibrated rays; reject back/grazing surfaces, depth-occluded or mask-invalid samples and bilinear samples touching non-skin. Weight by angle cosine^4 and distance from mask edge. Blend in linear RGB. Near camera silhouette edges the depth test is approximate at pixel resolution; inspect close-ups, set depth tolerance to world units (default 1 mm), increase image resolution before relaxing it.
4. Inspect `projected_rgba.png` (transparent where unknown), `atlas_mask.png`, `observed_mask.png`, `view_support.png` (fraction of input views that contribute, not calibrated confidence), `coverage_heatmap.png` (green observed, red unobserved), `projection_report.json` (hashes, cameras, coverage, runtime). Look for seams, double eyes, stretched nostrils, hair bleed and unobserved regions, independently annotate actual texture landmarks. Never equate total-atlas coverage with visible face quality; report regional/heldout coverage.
5. Reserve holdout manifest `assets/templates/holdout_manifest.json`, use `python scripts/evaluate_photo_holdout.py inputs/holdout.json --projection reports/front_only --projection reports/projection --out reports/holdout`. Both projections must use identical mesh/material and occlusion policy. This computes skin-mask IoU and reports each candidate's own-support coverage and MAE/PSNR plus same-pixel common-support error; masks prevent cherry-picking. Inspect residuals and raw source overlay. Hash checks detect only exact duplicate inputs; manually verify independent capture. RGB residuals include appearance, camera and lighting differences, not intrinsic albedo error. Require calibrated comparable acquisition and avoid claiming likeness or photorealism from metrics.
6. Only if desired use `compose_skin_atlas.py reports/projection --out textures/composed --fallback textures/authorized_compatible.png --fallback-provenance 'license and atlas version' --padding 8`. It preserves observed pixels, requires explicit same-layout fallback for unknown skin and stores `inferred_mask.png`; no automatic mirroring or generative filling. Outside-shell dilation is limited; inspect mips/seam padding. The basecolor remains DRAFT: de-light using controlled/cross-polarized source or artist review, independently inspect skin texture and bake with PBR maps; attach final image to Blender Principled Base Color (sRGB) using same UV0, then export new candidate. Run all v3 release gates on the new GLB, not old evidence. Do not ship diagnostic UV asset or raw photo-derived colors as albedo.
