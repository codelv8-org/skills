# Web delivery, glTF, performance and viewer integration

## Budgets are planning thresholds, not universal guarantees

| Profile | Total exported triangles, initial target | Indicative GLB size | Texture strategy |
|---|---:|---:|---|
| Icon / very simple NPC | 300-1,500 | 2 MB | Solid colors / 256-512 px if needed |
| Mobile avatar | 1,500-5,000 | 5 MB | Solid / 512-1024 px |
| Balanced web character | 5,000-12,000 | 12 MB | 512-1024 px atlas or palette |
| Single hero detail | 12,000-25,000 | 20 MB | 1-2K if detailed texture is necessary |

**These are configurable engineering heuristics.** Include all body, face, hair, clothes and gear. Rendering 30 such NPCs may require much lower per-character cost than rendering one portfolio hero. Account for number of draw calls, materials, bones, morph targets, texture memory, lights, transparency, animation evaluation, and actual GPU/device FPS. Actual GLB bytes and exported triangles may exceed Blender face count because of splits at UV seams, hard normals and materials.

## Coordinate convention

- In **Blender authoring**: `+Z` is up, `-Y` character forward; `+X` character's anatomical left. Keep floor at Z=0 and 1 Blender unit = 1 m unless the brief states otherwise. Apply transforms intentionally, not blindly to animated armatures.
- On **glTF 2.0 export**: glTF files have +Y up; inspect how Blender's glTF exporter converts axes. A common conversion makes Blender -Y forward become glTF +Z forward. *Verify direction by loading the actual GLB with a visible front marker*, do not trust an assumption.
- Use centered root to assist consistent placement. Preserve a stable pivot for animation, avoid negative/nonuniform scale at the skinned mesh root unless tested.

## Standard output

`source/character.blend` (if authored); `export/character.glb`; `previews/clay/`, `previews/final/`, `previews/poses/` as evidence; `reports/structure.json`, `reports/release_gates.json`; `README.md` for rights, style, transforms, budgets, material atlas, clips, viewer notes, fallback and unperformed checks.

## Browser validation

1. Load the exact GLB in the intended engine, use orbit controls and an orthographic/suitable perspective camera, and compare front/profile/back silhouette.
2. Inspect with both ambient/fill and directional lighting to reveal faceted normals, material-response inconsistencies and clipped geometry.
3. Check material alpha behavior, hair/decal sorting, shadow artifacts, z-fighting, unexpected duplicate face visibility and imported scale.
4. Trigger each requested animation. Ensure bones animate and meshes follow them; distinguish rigged from segmented rigid; check clip loops and root motion.
5. Measure first-load bytes/time and frame performance on real mobile and desktop targets. Build a crowded sample if the user will display many characters simultaneously.
6. Test network/CORS and HTTPS access in deployed environments. Use cached assets and proper disposal; do not leak WebGL resources while mounting/unmounting characters.
7. If applying Draco, KTX2/Basis or Meshopt, wire and test matching decoders supported by the current GLTFLoader. Maintain an uncompressed fallback if appropriate; never export compression without viewer support.

## Starter

`assets/web/CharacterViewer.tsx` is a React Three Fiber example. Its `animationName` is optional and skipped safely when no clips exist. For static character previews, install `three`, `@react-three/fiber`, `@react-three/drei`, and `three-stdlib`. Run a real browser smoke test on this starter before claiming web-ready.

The required zero-CDN preview is now `assets/preview/` generated by `scripts/build_preview_site.py`; the existing React Three Fiber `assets/web/CharacterViewer.tsx` remains a production integration example for projects already using React.
