# Strict approved metadata contract v2.0

Before reading, obtain independent confirmation from DBA/Data Owner that the exact artifact is schema-only, sanitized, in scope and approved for the requested audience. Do not assume a filename or a boolean proves consent. For synthetic templates use the bundled fixture with template status. Reject any real data; no attempt to clean it after access.

The JSON contract is an explicit allowlist. Unknown keys at every level, duplicate JSON keys, raw defaults/comments, sample_rows, records, examples, SQL expressions, payloads and statistics are forbidden. All keys below are required except the optional `definitions` and `lineage` arrays and optional classifications (if omitted/null they resolve to Restricted). Use opaque labels, not hosts, real people, credentials or source paths. Identifier syntax: ASCII letters/underscore followed by letters/digits/underscore; source, revision and scope labels follow the same pattern. This conservative version does not support punctuation/Unicode in physical identifiers; request reviewed aliases with an approved mapping outside this tool rather than silently rename. Preserve identifier case. Type is a reviewed identifier or a recognized SQL type phrase (no literal expressions or type parameters); dimensions are separate. For unknown length/precision/scale/nullability use null. No raw ENUM/SET values, generated expressions, comments or default values even if believed safe. Business definitions are independent curated text, never extracted from raw comments; owner must review before agent access.

- Top level: `contract_version` = `2.0`; `system_label`; `engine` = mysql/mariadb/postgresql/sqlserver/sqlite/other; `schema_revision`; `scope_id`; `status` = verified/partial/template; `approval`; `sources`; `objects`; optional `definitions`, `lineage`.
- `approval`: `role` = DBA/DataOwner/Synthetic; `reviewed`, `metadata_only` must be true; `audience` = internal/restricted/public; Synthetic only with status template, and template only with Synthetic. Public requires independent disclosure approval for all included metadata, not just this label.
- `sources`: list of unique opaque source IDs, no paths or secrets. At least one.
- `objects`: each has `schema`, `name`, `kind` = table/view/materialized_view/other, `source_id`, `classification` (optional), `columns`, `keys`, `foreign_keys`. Identity = schema.name. At least one column per object; empty object list only if explicitly partial/template, not verified.
- Columns: `name`, `ordinal` (positive unique), `type`, `length`, `precision`, `scale`, `nullable` (bool/null), `source_id`, optional `classification`. Negative scale allowed for engines supporting it. Unknown numeric values use null. No default/comment fields.
- Keys: `name`, `kind` = primary/unique, `columns` (ordered unique names), `source_id`. At most one PK; PK columns cannot have nullable=true. Unknown PK nullability is reported as unknown. FK: `name`, `columns`, `target_schema`, `target_name`, `target_columns` (ordered), `source_id`. FK target must be an included object with a matching approved PK/unique column set; preserve order of FK mapping; if referenced key evidence missing or external, request complete curated scope or omit the edge and mark coverage partial. A unique column set may be referenced in another column order.
- `definitions` optional: records with `schema`, `object`, `column` (null for object definition), `definition`, `grain`, `format`, `unit`, `owner_role`, `source_id`, `status` (verified/proposed). `grain`/`owner_role` only at object level, `format`/`unit` only at field level; unused values null. Text fields max 300 characters, one line, no real records, SQL, URLs, credentials, markup or copied raw comments. Use only owner-curated plain text and role labels. Proposed meanings are explicitly distinguished; no inferred facts. An absent definition is unknown. Do not generate fictitious clinical meanings. Use null if not approved.
- `lineage` optional: explicit owner-approved directed object mappings with `from_schema`, `from_object`, `to_schema`, `to_object`, `kind` (derived_from/replicates/transforms), `source_id`. Source is upstream, target downstream. Do not equate FK with lineage, infer from names or read ETL code. No mapping means unknown, not no lineage.

Classification vocabulary: Public, Internal, Confidential, Restricted, Unknown (null/omitted also unknown). Unknown is represented as `Unknown -> Restricted`; classification floors for common clinical, person-linked, credential identifiers are Restricted. A name heuristic is supplementary and not exhaustive; require owner review for semantics. A declared class lower than a restricted field is escalated to effective Restricted (not silently trusted). Objects inherit the highest effective field classification. Classification is risk of the data represented, distinct from approval to disclose the metadata itself. Public publication does not follow automatically from any class. See privacy boundary.

For migration from either v1 skill, preserve old evidence, definitions and relationships only after owner projection and approval; no automatic ingestion of old untrusted manifests. Do not treat legacy Unknown as safe. Do not manufacture an approval object.
